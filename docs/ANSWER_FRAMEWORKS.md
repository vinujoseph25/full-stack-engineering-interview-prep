# Senior Engineering Answer Frameworks

Use these structures to produce concise, experience-led answers rather than memorised definitions.

## Technical questions

**Concept → Why it matters → When to use → Example → Trade-offs**

1. Define the concept in one or two sentences.
2. Explain the engineering problem it solves.
3. Give the situations where you would choose it.
4. Ground the explanation in a realistic production example.
5. Finish with alternatives and trade-offs.

## Architecture questions

**Requirements → Constraints → Architecture → Data/API → Reliability → Security → Observability → Scaling → Trade-offs**

Start by clarifying functional and non-functional requirements. State assumptions before selecting technologies.

## Debugging questions

**Symptoms → Scope → Evidence → Hypothesis → Experiment → Fix → Prevention**

Prefer measurable evidence such as logs, traces, metrics, profiles, error rates, latency, or resource utilisation.

## Performance questions

**Baseline → Bottleneck → Intervention → Measurement → Regression protection**

Avoid claiming an optimisation without describing how the improvement was measured.

## Leadership questions

**Context → Problem → Options → Decision → Influence → Outcome → Learning**

Show how you created alignment, handled disagreement, managed risk, and communicated the decision.

## Behavioural questions

Use **STAR**, then add engineering judgement:

**Situation → Task → Action → Result → Learning**

Strong answers quantify the result where possible and explain what you would repeat or change.

## Senior-level signal

A senior answer should demonstrate:

- Trade-off awareness rather than tool preference
- Production reliability and operational thinking
- Security and accessibility by design
- Performance measured with evidence
- Clear communication with technical and non-technical stakeholders
- Ownership beyond implementation
- Mentoring and team-level impact
